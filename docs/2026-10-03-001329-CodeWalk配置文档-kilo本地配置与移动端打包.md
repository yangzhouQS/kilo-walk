> 依据项目实测文件整理：`README.md`、`AGENTS.md`、`Makefile`、`ADR.md`（ADR-049）、`ai-docs/kilo_server.md`、`CONTRACT_MATRIX.md`、`install.ps1`/`install.sh`、`android/app/build.gradle.kts`，以及本机 Kilo 全局配置目录实测（2026-10-03）。

## 一、项目概览

CodeWalk 是 [OpenCode](https://github.com/anomalyco/opencode) server 模式的原生跨平台客户端（OpenCode 家族还包括 Kilo CLI/TUI 内嵌服务器，见 ADR-049）。

| 项 | 内容 |
|---|---|
| 框架/语言 | Flutter / Dart |
| 状态管理 / HTTP / DI / 存储 | Provider / Dio / GetIt / SharedPreferences |
| 设计体系 | Material Design 3（Material You），五档密度，响应式 |
| 支持平台 | Linux、Windows、macOS、Web、Android（iOS 未提供发布渠道） |
| 架构 | Clean Architecture：Domain / Data / Presentation 三层 |
| 许可 | AGPLv3（开源）+ 商业双许可 |
| 关键文档 | `README.md`、`BEHAVIOR.md`（现行行为）、`ADR.md`（架构决策）、`CODEBASE.md`（结构）、`CONTRACT_MATRIX.md`（服务端契约矩阵）、`ai-docs/`（OpenCode/Kilo 契约锚点） |

**核心工作流约定（摘自 `AGENTS.md`）：**

- 验证门使用 `make check`（deps + gen + analyze + coverage-tool fixtures + 全量测试），迭代期用聚焦测试。
- Android 可测构建使用 `HEY_CAPTION="具体描述" make android`，不要直接 `make precommit`。
- ARM64 Linux 主机上 APK 构建不可靠，发布 APK 走 GitHub Actions。
- 版本发布使用 `make release V=patch|minor|major`。

## 二、本地 Kilo 的配置

### 2.1 Kilo 服务器是什么

Kilo CLI/TUI（`kilo.exe`）内嵌了一个 HTTP 服务器，CodeWalk 通过它与 Kilo 会话同步（LAN 场景）。ADR-049 判定：**Kilo 服务器是 OpenCode 家族超集**，CodeWalk 采用「策略 A：直接连接 + 容错解析」，无需数据源分叉。

| 项 | 默认值 |
|---|---|
| 监听地址 | `127.0.0.1:4096`（仅回环；实测版本 7.6.2–7.7.7） |
| 局域网访问 | 需 `--hostname 0.0.0.0` 支持或操作系统级端口转发 |
| 认证 | Basic Auth（`Authorization: Basic ...`，由 `DioClient` 按 origin 注入，与 OpenCode 一致） |

### 2.2 Kilo 本地目录结构（Windows 本机实测）

| 路径 | 用途 |
|---|---|
| `C:\Users\<用户>\.config\kilo\` | 全局配置根目录。实测含：`kilo.jsonc`（主配置）、`agents\`（子代理）、`plugin\`（插件）、`.cache\`、`package.json` / 锁文件（插件运行时依赖）等 |
| `C:\Users\<用户>\.local\state\kilo\` | 运行状态目录（会话状态等） |

服务器 `GET /path` 端点返回这些位置（实测样例）：

```json
{
  "home": "C:\\Users\\10456",
  "state": "C:\\Users\\10456\\.local\\state\\kilo",
  "config": "C:\\Users\\10456\\.config\\kilo",
  "worktree": "/",
  "directory": "H:\\2026code\\..."
}
```

> 注意：Windows 路径含反斜杠，`worktree` 实测为 `"/"`，路径工具不能假设 POSIX 格式。

### 2.3 主配置文件 `kilo.jsonc`

Schema：`https://app.kilo.ai/config.json`。关键字段（实测摘录）：

```jsonc
{
  "$schema": "https://app.kilo.ai/config.json",
  "model": "zhipuai-coding-plan/glm-5.3",   // providerID/modelID 字符串
  "small_model": "...",
  "subagent_model": "...",
  "command": {},
  "skills": { "paths": [], "urls": [] },
  "snapshot": true,
  "plugin": ["..."],
  "remote_control": true
}
```

`model` 的 `providerID/modelID` 字符串格式与 CodeWalk 现有模型选择同步逻辑兼容。

### 2.4 Kilo 服务器契约（ADR-049 摘要）

CodeWalk 消费的 OpenCode 表面在 Kilo 服务器上全部可用（探测均 200 OK）：

- 会话：`/session`、`/session/{id}`、`/session/{id}/prompt_async`、`/session/status`、会话动作（`share` `diff` `todo` `revert` `unrevert` `init` `summarize` `command` `abort` `fork`）
- 实时事件：`/event`、`/global/event`（SSE，`id`/`type`/`properties` 信封一致）
- 配置：`GET/PATCH /config`（含 `/config/effective`、`/config/overlay`）
- 目录：`/provider`、`/agent`、`/command`、`/path`
- 项目/文件：`/project`、`/file`、`/file/content`、`/find`、`/find/file`、`/find/symbol`
- VCS/Worktree：`/vcs`（`apply` `diff` `status`）、`/experimental/worktree`
- 权限/问答：两代权限端点并存；`/question/{requestID}/reply|reject`
- PTY 终端：`/pty`、`/pty/{id}/connect`、`/pty/{id}/connect-token`、`/pty/shells`（比上游快照更丰富）

**Kilo 特有超集**（CodeWalk 暂不消费，使用前须能力门控）：
`/kilo/*`（cloud、auth-status、notifications）、`/kilocode/*`（agent-manager、background-jobs、notebook、marketplace）、`/tui/*`、`/api/*`（含 `/api/pty`）、`/memory/*`、`/mcp/*`、`/network/*`、`/suggestion/*`、`/sync/*`、`/remote/*`、`/background-process/*`、`/indexing/*`。

### 2.5 CodeWalk 侧的 Kilo 连接配置

1. 启动应用 → 侧栏 **Settings → Add Server**。
2. `ServerProfile` 新增咨询字段 `serverKind`：
   - `opencode`（默认，历史档案兼容回退）
   - `kilo`
   - 两者线协议一致；`kind` 目前仅驱动诊断文案与后续能力门控。
3. 服务器 URL：
   - 本机：`http://127.0.0.1:4096`
   - 手机/局域网：`http://<电脑局域网IP>:4096`（Kilo 预设条目规划自动填充，ADR-049 后续项）
4. Basic Auth 按需配置（Kilo 服务器密码机制在首次 LAN 部署时确认）。

**M2 前待验证项**（`ai-docs/kilo_server.md`）：

1. 完整 SSE 事件类型全集与 `chat_realtime_model.dart` 期望比对（未知类型必须安全忽略）。
2. `prompt_async` 与服务器分配 ID 的请求/响应往返。
3. PTY 连接握手（`/pty/{id}/connect` vs `connect-token`）与 `terminal_remote_datasource.dart` 假设比对。
4. `PATCH /config` 忙态语义（ADR-019 延后路径）。

## 三、手机端的安装配置

### 3.1 Android 安装

| 渠道 | 操作 |
|---|---|
| 官方快捷安装 | Android 浏览器打开 [install.cat/verseles/codewalk](https://install.cat/verseles/codewalk) 直接下载 APK |
| GitHub Releases | 从仓库 Releases 页下载 `codewalk-android-*.apk`（arm64-v8a） |
| 本地构建 | `make android` 产物见第四节，adb/sideload 安装 |

- 应用支持**应用内更新**：自动检查 + 直接安装。
- APK 为 arm64-only（`--target-platform android-arm64`），覆盖主流现代设备。

### 3.2 首次启动与服务器配置向导

1. 首次打开（未配置任何服务器）进入**设置向导**，必须配置至少一个 OpenCode/Kilo 服务器后才能使用（无服务器 = 无功能，聊天输入被阻止）。
2. 向导内 **Quick setup**：在终端按提示启动服务器；服务器 URL 默认 `http://127.0.0.1:4096`（手机上应改为电脑的局域网 IP）。
3. 手机连接电脑服务器的推荐启动方式：

   ```bash
   # OpenCode 服务器（按需开放 CORS 与监听地址）
   opencode serve --hostname 0.0.0.0 --port 4096 --cors "https://你的站点"

   # Kilo 内嵌服务器：默认仅 127.0.0.1:4096，LAN 需 --hostname 0.0.0.0 或端口转发
   ```

4. 仅当服务器要求时配置 Basic Auth；保存后可随时切换默认/激活档案。
5. 健康检查：默认每 10 秒；蜂窝"省流"标准档降为每 1 分钟一次、仅查激活服务器；激进档 30 秒一次（状态控件显示 `Saver` 徽标）。
6. 健康检查失败是**诊断性而非阻断性**：失败档案保留在 `Settings > Servers`，可编辑/重试/删除；应用进入降级状态（可访问设置等非服务器界面），服务器恢复健康后聊天自动可用，无需重启或重新引导。

### 3.3 桌面端安装（对照参考）

```powershell
# Windows（PowerShell）：装到 %LOCALAPPDATA%\CodeWalk，加 PATH + 开始菜单快捷方式
irm install.cat/verseles/codewalk | iex
```

```bash
# Linux & macOS：装到 ${XDG_DATA_HOME:-$HOME/.local/share}/codewalk-app
curl -fsSL install.cat/verseles/codewalk | sh
```

- 重复执行同命令 = 更新/重装到最新 GitHub Release；安装器自动选平台资产（x64/arm64）。
- 运行中更新采用"暂存 → 关闭进程 → 应用 → 重启"两阶段模式，不删用户数据。

## 四、移动端的打包配置

### 4.1 前置要求

| 依赖 | 版本/说明 |
|---|---|
| Flutter SDK | >= 3.8.1（非交互 shell 记得 `export PATH="$HOME/flutter/bin:$PATH"`） |
| JDK | 17（`jvmTarget`/`sourceCompatibility` 均 17） |
| Android NDK | `28.2.13676358` |
| 签名密钥库 | 必需，release 构建强制校验 |
| 其他 | core library desugaring（`desugar_jdk_libs:2.1.5`）、`androidx.browser:1.9.0` |

### 4.2 签名配置（关键）

**`android/key.properties`**（不入库，CI/本机自行生成），必需四项：

```properties
storeFile=你的keystore路径
storePassword=存储密码
keyPassword=密钥密码
keyAlias=密钥别名
```

- `make android` 前置硬校验：**缺失或字段不全直接拒绝构建**（防止 debug 签名的"release" APK 流出）。
- `storeFile` 解析顺序（Makefile 与 `build.gradle.kts` 双侧一致）：
  1. `~/` 前缀 → 展开 `$HOME`
  2. 绝对路径存在即用；否则尝试映射到本机 `$HOME` 下同名相对结构
  3. 相对路径依次尝试：`$HOME/<path>` → `<path>` → `android/<path>` → `android/app/<path>`
- Gradle 侧（`android/app/build.gradle.kts`）：任务名含 `release`/`bundle`/`publish` 时强制要求 release 签名；`key.properties` 不存在时仅允许 debug 签名（本地开发）。

### 4.3 应用标识与版本号

| 项 | 值 |
|---|---|
| applicationId / namespace | `com.verseles.codewalk` |
| compileSdk / targetSdk / minSdk | 跟随 Flutter 插件默认（`flutter.compileSdkVersion` 等） |
| versionName | 取 `pubspec.yaml` 的 `version:` 名称段（如 `1.244.0`） |
| versionCode | 构建时计算：`unix时间戳 + 2001`（`ANDROID_BUILD_CODE_OFFSET=2001`），且强制大于 `pubspec.yaml` 中的 build 号（否则 +1 兜底） |

构建后自动校验 `output-metadata.json`：`versionName` 必须等于 pubspec 名称段、`versionCode` 不得低于计算值，防止版本错配。

### 4.4 打包命令与产物

```bash
# 1. 依赖与代码生成（若未做过）
flutter pub get && dart run build_runner build --delete-conflicting-outputs

# 2. 签名 release APK（arm64-only）
make android

# 3. 需要上传到 hey 通道的可测构建（caption 必须具体，禁止泛泛描述）
HEY_CAPTION="修复聊天页滚动回弹" make android
```

产物路径（`build/app/outputs/flutter-apk/`）：

| 文件 | 用途 |
|---|---|
| `codewalk.apk` | 固定名副本 |
| `codewalk-android-<版本名>+<versionCode>-<git短哈希>[-dirty].apk` | 上传副本（工作区不干净自动加 `-dirty`） |

构建成功后自动执行 `HEY_ALLOW_DUPLICATE=1 HEY_SYNC=1 ~/bin/hey -f <上传副本> "<caption>"` 推送。

### 4.5 发布流程（Release）

```bash
# 前提：工作区干净（make release 只提交版本号变更）；可选公告（≤300 字符英文单行，进应用内 What's-new）
ANNOUNCE="Fix chat scrolling on mobile" make release V=minor
make release V=patch   # 或 major
```

`make release` 自动完成：

1. 按 `V` 计算新版本号（patch/minor/major），build 号用时间戳规则；
2. `tool/release/changelog.py update` 更新 `CHANGELOG.md`（`## vX.Y.Z - YYYY-MM-DD` 唯一标题、新版本在前，保持机器可读以供应用内发布历史解析）；
3. 写 `pubspec.yaml` 的 `version:`，提交 `release: cut vX.Y.Z`，打 annotated tag，`git push --follow-tags` 触发 CI 与 Release 工作流。

### 4.6 移动端打包注意事项汇总

- **验证门**：代码稳定后先 `make check` 一次，再 `make android`；微调修复只需聚焦验证，勿滥用全量检查。
- **ARM64 Linux 主机**无法可靠产出 APK —— 发布 APK 一律走 GitHub Actions；`make check` 在 ARM64 可用。
- 静态文案/文档改动不需要 `make check` / `make android`。
- 通知图标 `ic_stat_codewalk.png` 五档密度（mdpi 24 → xxxhdpi 96 px），由 `make icons-tray` 从 `assets/images/tray_mono_master.png` 派生，改动后可用 `make icons-check` 校验尺寸与透明度。
- 版本错配、缺 `key.properties`、keystore 找不到均会让 `make android` 快速失败并给出明确提示。

## 五、常用命令速查

| 命令 | 说明 |
|---|---|
| `make check` | 全量验证门：deps + gen + analyze（含问题数预算 337）+ 测试 |
| `make check-fast` | 同上但仅快速测试（排除 slow/integration 标签） |
| `make android` | 构建 arm64 签名 release APK（需 key.properties） |
| `HEY_CAPTION="..." make android` | 构建并通过 hey 上传可测 APK |
| `make web` | 构建 Web 到 `build/web`（`WEB_BASE_HREF=/子路径/` 可改 base href） |
| `make desktop` | 按宿主 OS 构建桌面版（含版本一致性校验） |
| `make release V=patch\|minor\|major` | 版本提升 + CHANGELOG + 提交 + tag + 推送 |
| `make icons` / `make icons-check` | 重新生成 / 校验全部图标产物 |
| `make smoke` | 对 OpenCode 服务器的集成冒烟测试 |
| `make clean` | `flutter clean` + 恢复依赖 |
